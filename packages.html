Packages and signing key

Signed Fedora 44 packages and the installer for OpenVIBES.

Install the platform

sudo sh -c "$(curl -fsSL https://openvibes-project.github.io/install.sh)"

It adds this repository, installs the administration tool and opens its Setup. No output at all means the download failed: check your connection and run it again. Safer: download install.sh, read it, then run sudo sh install.sh.

In Setup, choose the assistant and answer Y to download the model. To add it later, turn the assistant on in Setup: it downloads the model itself.

Install without internet

Fedora 44, x86_64. The offline kit holds every platform package and its Fedora dependencies, PostgreSQL included; its installer never uses the internet.

  1. Download openvibes-platform-<version>-offline-fedora44.tar from the latest platform release, and optionally the model (below), in any browser.
  2. Copy both to the server, into the same folder.
  3. tar xf openvibes-platform-<version>-offline-fedora44.tar && sudo ./openvibes-offline/install

The kit checks its own signature with the package key below (fingerprint 710A D8AF B7AF E6E8 64C0 CDC4 E134 BAF3 7786 DA36).

The assistant's model, optional: Qwen3-4B-Q4_K_M.gguf (about 2.5 GB, from its publisher on Hugging Face; Apache 2.0). SHA-256:

7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5

Add an agent

In the console: Enrollment → Add a host, then Copy CLI install or Install package. On the platform host, sudo openvibes-admin agent command prints the same command.

The repositories

The installer adds the right one for you; all are x86_64 and signed with the key below. Released versions: releases.txt.

  • dnf (Fedora 44; AlmaLinux and Rocky Linux 9+, agent only): openvibes.repo in /etc/yum.repos.d/, and the key, once you have checked its fingerprint, as /etc/pki/rpm-gpg/RPM-GPG-KEY-openvibes (the repository file names it there, so dnf never fetches a key itself). On AlmaLinux and Rocky, the installer points the repository at the Fedora 44 folder: the agent package is the same file.
  • apt (Debian 12+, Ubuntu 22.04+, agent only): the key as /etc/apt/keyrings/openvibes.asc, and in /etc/apt/sources.list.d/openvibes.list: 
    deb [signed-by=/etc/apt/keyrings/openvibes.asc] https://openvibes-project.github.io/deb ./
  • pacman (Arch, agent only): the key added with pacman-key --add openvibes.gpg and pacman-key --lsign-key (fingerprint below), and in /etc/pacman.conf: 
    [openvibes]
SigLevel = Required DatabaseRequired
Server = https://openvibes-project.github.io/arch/$arch

The package key

openvibes.gpg, fingerprint

710A D8AF B7AF E6E8 64C0 CDC4 E134 BAF3 7786 DA36

Check it with gpg --show-keys openvibes.gpg. The installer refuses a key with another fingerprint.
